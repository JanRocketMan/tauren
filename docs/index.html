Tauren

A from-scratch learning reimplementation of the Tau coding agent

Goal

This project exists so you can understand how Tau works by rebuilding it yourself, one small task at a time.

You do not copy Tau. You reimplement it. Each task gives you a spec, a set of tests, and enough concepts to write the code with your own hands. The tests are the contract: when they pass, the piece is done.

This course follows the Feynman method: you learn by teaching. You are not building this for yourself only. You are building a course that others can follow. Every task ends with you being able to explain the piece to another person. If you cannot explain it, you have not learned it yet.

Scope

The target architecture mirrors Tau's three-layer split:

LayerRoot packageResponsibility
1ai (planned)Provider and model streaming
2agentPortable agent harness, loop, tools, events, sessions
3coding (planned)CLI app, resources, skills, extensions, commands, TUI

Layer 2 is the reusable brain and it is the current focus. Layers 1 and 3 plug into it later. Our agent package maps to Tau's tau_agent, so you can diff any finished file against /home/ubuntu/tau/src/tau_agent/... after you write it.

Out of scope for now:

  • Real provider API keys and live model calls
  • The Textual interactive TUI
  • OAuth flows, cloud sessions, release tooling

Everything above is reachable later if you want to go that far.

The learning loop

Every task runs through two stages, recorded as two commit types:

  1. task: commits add work. The teacher ships the spec, the tests, and the code skeleton in one commit
  2. done: commits implement work. The learner makes the tests pass and keeps every check clean in one commit

The loop itself looks like this:

  1. Read the task spec in docs/task-NN.html, which opens with the commit it is based on
  2. Read the "concepts" section until the pieces make sense
  3. Implement the missing code in src/
  4. Run the quality gates until tests pass and checks are clean
  5. Commit as done: <what you implemented>
  6. The teacher reviews the done: commit and guides you
  7. Diff your work against the reference and read the matching phase notes
If you get stuck for more than a few minutes, peek at the reference phase notes in /home/ubuntu/tau/dev-notes/architecture/. They explain why each piece exists. The current source in /home/ubuntu/tau/src/ is the last resort, and only for reading, not for copying.

Quick start

cd ~/tauren
uv venv --prompt tauren
uv sync
uv run pytest

The --prompt tauren flag labels the virtual environment so the shell prompt shows (tauren) instead of (.venv). It works on a fresh venv and on an existing one, and it keeps installed packages.

Learning Progress

Course completion by task:

1 of 9: task 01 in progress

Line progress against the reference, module by module: 

uv run python tools/progress.py

The test runner is gamified too. A green session ends with a rocket, a red session ends with a sad cat. The rocket means the next commit is a done: one.
