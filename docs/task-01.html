Concepts

The transcript

A transcript is the conversation state that the agent and the model work with. Everything that happens in a session is recorded as a sequence of messages: 

User asks to read README.md
Assistant calls read
ToolResult returns file contents
Assistant sees the contents and answers

This task gives you the three message types that build that sequence.

Why shared types come first

Tau's core rule is that the agent layer must be provider-neutral and UI-neutral. The message model must not mention OpenAI, Anthropic, Rich, Textual, or local files. Later, one set of message objects will flow into any provider adapter and out of any frontend. The JSON aliases make tool arguments and payloads type-safe without tying them to a specific provider SDK.

  4. Run the quality gates until everything is green

What to implement

In messages.py the following pieces are stubbed:

  • UserMessage.text - return self.content
  • AssistantMessage.text - return self.content
  • ToolResultMessage.text - return self.content
  • message_text(message) - return message.text for each concrete type in the AgentMessage union

The dataclass fields are already defined for you. Read each one and make sure you understand why it exists before you touch the bodies. If a field is mysterious, look at the test that uses it.

There is more than one correct way to write message_text. The simplest correct version is one line per message type. Do not over-engineer it yet. Later tasks will grow the message family and the function with it.

Think about

  • Why is content just a plain string here, while Tau's current code uses content blocks with text, thinking, and images?
  • Why does AssistantMessage carry text and tool calls together?
  • What problem does the AgentMessage union solve for functions that accept a whole transcript?
